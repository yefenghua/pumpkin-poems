## 1. 视觉依据与工作分工

### 1.1 采用的设计方向

采用用户提供的「今天 / 静夜思学习 / 我的成长册」三屏原型：绘本式国风场景、温暖的南瓜伙伴、奶油色阅读界面。

不采用后来生成的杂志拼贴风、超大黑体标题和纸片南瓜方案。

参考图是视觉与构图依据，不是用于直接切图上线的页面。所有文字、按钮、导航、统计与诗句均需使用原生组件实现。

### 1.2 明确的责任边界

| 工作 | 负责人 | 交付要求 |
|---|---|---|
| 背景、角色、场景插画、主题封面、装饰图片的生成与修订 | 本对话中的 Codex（设计与图片生成方） | 统一风格，按素材清单提供图片文件和交付说明 |
| 图片视觉一致性、角色一致性、透明背景及构图检查 | 本对话中的 Codex | 生成后检查，必要时修订 |
| Swift / SwiftUI 界面、导航、状态与交互 | 接收本文档的实现 AI | 原生实现，接入现有业务逻辑 |
| 将已交付图片导入 Asset Catalog、配置显示与裁切 | 实现 AI | 根据交付素材配置资源名称、尺寸和布局 |
| 自适应、安全区、动态字体、VoiceOver 与性能验证 | 实现 AI | 在目标设备及支持的系统版本上验证 |

**实现 AI 不负责生成插画，不需要另找图片生成服务，也不要自行寻找风格不同的替代图片。所有需要生成的图片均由本对话中的 Codex 提供。**

本次直接接入已交付的正式素材。后续新增图片尚未交付时，实现 AI 可先搭建对应布局与素材接口，并使用明确标记的中性占位区域。不要把占位界面当作最终视觉成果，不要用 Emoji 或系统图标代替南瓜角色和主要场景。

本文所列正式素材已生成并整理为资源包。图片实际像素尺寸、透明情况及使用说明见 `docs/design/ui-delivery/manifest.json` 与 `README.md`。后续新增图片仍由本对话中的 Codex 生成。

## 2. 整体设计目标

为「南瓜古诗」设计一款亲切、精致、有探索感的古诗学习 App。

核心体验是「跟着南瓜伙伴走进诗里的世界」：首页随诗歌主题呈现月夜读书、田园读书或树下读书场景，诗歌详情延续对应诗意，成长页是逐渐收集起来的风景册。

界面分为三层：

1. **场景层**：山水、天空、月亮、花草，建立情绪。
2. **内容层**：暖白色纸张承载诗歌、学习任务和说明。
3. **陪伴层**：首页和成长页的南瓜已经画入场景；解释卡片的小南瓜仍作为独立助手，提供引导和反馈。

通过背景延伸、场景内自然融合的角色、卡片与场景交叠、收藏封面轻微错位，减少规整网格带来的机械感。正文和操作区仍需保持清晰稳定。

## 4. 字体、文案与排版

操作与说明文字优先使用系统中文字体。诗句可使用有授权的中文楷体或宋体；字体未确定时先使用系统字体，不阻塞布局开发。

| 文字类型 | 基准字号与字重 |
|---|---|
| 首页「今天」、成长页标题 | 32–34，Bold |
| 首页引导语 | 21–23，Semibold |
| 卡片诗名 | 30–32，Bold |
| 详情页顶部诗名 | 22–24，Semibold |
| 诗歌正文 | 30–34，Medium / Semibold |
| 解释文字 | 17–18，Regular |
| 主要按钮 | 19–20，Semibold |
| 小标签与作者信息 | 14–16 |
| 底部导航标签 | 11–12，优先遵循原生组件行为 |

- 所有标题、诗句、按钮文字和统计数字都使用原生 `Text`。
- 支持动态字号，不把固定高度作为文字容器的硬限制。
- 不把诗名、说明或操作文字烘焙进图片。
- 参考图使用繁体中文，实际项目遵循现有语言设置。
- 简繁切换后同步更新诗文与界面文案；下文简体文案仅用于说明。
- 「贝贝」作为示例角色名，若项目已有正式名称则沿用正式名称。

## 5. 首页：三套主题的诗意场景

结构：沉浸式场景 → 继续学习任务 → 两个辅助入口 → 底部导航。

### 5.1 顶部场景

- 从屏幕顶端延伸到首张学习卡片后方，包含安全区背景。
- 基准设备上总视觉高度约 350–390，实际随比例调整。
- 月与思乡：贝贝在月夜湖畔读书，远处明月、山影和暖灯亭台。
- 山水田园：贝贝在溪流和稻田旁读书，画面保留青山、村舍、竹柳。
- 四季景物：贝贝坐在桃花树下读书，保留蓝天、小鸟、飘落花瓣与草地，不再复用山水亭台构图。
- 左上方预留区域放置「今天」和引导语；月夜版用暖白文字，田园和四季版用深色文字，必要时增加克制的局部渐变以保证对比度。
- 首页角色已在图片中，位置与尺寸随整张图片变化，不再单独定位或叠加。完整呈现头顶藤柄、书本和树下位置。
- 场景底部与奶油色页面自然衔接。月夜图底部保留深色草地，可使用原生渐变遮罩或卡片交叠衔接，不重新绘制图片。

示例文案：

> 今天  
> 和贝贝一起，  
> 读懂一首诗

文字避开角色、复杂花叶和高对比细节，不依赖厚重阴影弥补可读性。

### 5.2 继续学习卡片

- 占满页面内容宽度，向上覆盖顶部场景约 24–36。
- 内容自然撑开，基准高度约 230–250。
- 使用奶油白纸面、细暖金描边与柔和阴影。
- 可在内侧增加一道低对比细描边，形成精装绘本感。

内容顺序：

1. 小标题「继续学习」。
2. 诗名「静夜思」。
3. 说明「读懂月光，也读懂思念」。
4. 全宽主按钮「继续学习」。

卡片右上按诗歌主题选用对应的 `art_continue_*` 插画，约占卡片宽度的 40%，向左淡出。月夜、田园、桃花树三种插画分别与首页对应。插画可延伸到标题附近，但文字背后必须干净。这里的「配套按钮图」指继续学习卡片的场景插画，金色操作按钮本身仍使用原生组件。

按钮使用浅金到金黄的轻微纵向渐变、细描边与浅阴影，右侧放 `chevron.right`。整体接近有轻微厚度的柔软贴纸，避免强烈高光。

没有历史学习记录时，改为「开启第一首诗」等对应引导，按钮连接真实学习流程。

### 5.3 两个辅助入口

「今日复习」和「飞花令」并排，间距 12，基准高度约 140–155。

- 今日复习：卷轴、毛笔、浅色花草。
- 飞花令：粉色桃花、花瓣与枝条。
- 标题位于左上，右下放白色圆形箭头。
- 整张卡片可点击，箭头表达方向，不额外形成重复焦点。
- 两张卡片使用不同插画构图，避免重复模板感。
- 大字号导致空间不足时改为纵向排列。

## 6. 诗歌学习页：主题场景与阅读纸面

### 6.1 顶部场景与导航

- 《静夜思》等月夜思乡题材使用夜空、明月、远山、湖面、窗棂和灯笼；田园与四季题材使用主题映射表对应背景。
- 基准视觉高度约 290–320，背景延伸至顶部安全区。
- 左侧返回按钮；诗名和作者靠左排列。
- 右侧提供文字与朗读语言选择器，例如「繁體」「粵語」。
- 选择器为浅奶油底、深色文字和向下箭头。
- 窄屏或大字号下，将选择器移至标题下方，不能挤压诗名。
- 语言选项仅展示项目实际支持的内容和音频。

月夜图是《静夜思》的对应场景，不应强制用于所有诗歌。田园图采用青山、溪流和村舍；四季图采用与首页同一棵开花的树及小鸟。月夜导航用浅色，另外两种背景导航用深色，并验证对比度。新增题材图片仍由本对话中的 Codex 生成。

### 6.2 阅读纸面与诗句

- 暖白色内容面板覆盖场景底部约 24–32。
- 顶部两个角圆润，建议圆角 28。
- 面板向下连续延伸，像一张展开的纸。
- 不再为每一句诗添加独立卡片或厚边框。

《静夜思》四句居中排列，基准字号 32，每行占约 62–68 高度：

> 床前明月光  
> 疑是地上霜  
> 举头望明月  
> 低头思故乡

当前诗句使用淡黄色圆角底色，左右保留约 24–32 外部空间，高亮覆盖该行阅读区域，不加明显阴影。

- 点击诗句后同步更新解释。
- 高亮切换动画约 0.2 秒。
- 选中状态通过无障碍属性表达，不仅依赖颜色。
- 长诗和七言诗支持自适应及滚动，不裁切正文。
- 不为保持一行显示而把字体缩到难以阅读；必要时调整排版。

### 6.3 「读懂这句」解释区

放在诗句下方，使用浅暖金描边容器：

- 左上：灯泡图标和「读懂这句」。
- 正文：一到三行容易理解的白话解释，内容较长时自然增高。
- 右上边缘：探出的南瓜头像，宽约 64–80。
- 为角色预留空间，避免挡住正文。

示例解释：

> 月光洒在地上，好像铺了一层霜。

角色可跨出卡片边界，但不能遮挡诗句或拦截按钮操作。

### 6.4 底部操作

用底部安全区固定操作栏：

- 左侧「听一听」：浅蓝底、蓝色扬声器图标。
- 右侧「开始背诵」：金黄色主按钮。
- 基准宽度比例约 1 : 1.6，间距 12。
- 底部避开 Home Indicator；正文滚动区域不得被操作栏遮挡。
- 大字号下可改为上下排列。

播放时「听一听」切换为明确的暂停状态，并同步突出当前朗读句。开始背诵进入独立的学习状态或页面。音频不可用时展示真实状态，避免按钮点击后无反馈。

## 7. 成长页：可收集的风景册

### 7.1 顶部氛围

- 浅色山水、云雾、草地和花朵构成背景。
- 左上标题「我的成长册」。
- 副标题「每一次复习，都有收获」。
- 使用 `scene_growth_with_mascot`，南瓜已融合在图片中间偏右，举起诗意卡片；不要再次叠加独立角色。图中卡片属于固定装饰，不代表用户实际获得的某一张卡片。
- 少量金色短线和花瓣表达开心与成就感。
- 标题区域背景保持浅、淡、干净。

### 7.2 主题收藏卡

三个主题：月与思乡、山水田园、四季景物。

- 采用竖向画册封面，宽高比约 0.58–0.64。
- 画面占主体，名称位于底部原生暖白标签区。
- 在 393pt 屏幕上，单张宽约 105–110、高约 180–190。
- 左右卡片可分别旋转约 −3° 和 +3°，中间保持稳定。
- 奶油色厚边、圆角与柔和阴影形成收藏卡质感。
- 旋转后仍应保留完整点击区域，避免被父容器裁切。
- 小屏幕或大字号模式改为横向滚动，不强行缩小文字。
- 未解锁状态结合降低饱和度、锁形图标与文字说明。
- 点击进入真实主题内容。

### 7.3 成长统计

下方使用一张整体浅色面板，内部三列，用细线分隔。

| 指标 | 图标方向 | 展示示例 |
|---|---|---|
| 已读过 | 书本 | 12 首 |
| 练习通过 | 幼苗 | 8 首 |
| 记忆较稳 | 日历勾选 | 5 首 |

图标放在浅金色圆形底座上，完成标记使用绿色小圆勾。数字必须来自真实学习数据，示例数字不能直接写死。三个指标分别代表接触、练习与记忆情况，具体计算沿用产品业务定义。

无记录时展示零值和温和的首次学习引导，不展示虚构成就。

## 8. 底部导航与原生交互

底部导航：今天 / 诗库 / 我的。

- 优先使用原生 `TabView`，根据目标 iOS 版本调整外观。
- 未选中为深暖灰，选中为橙金色。
- 图标参考 `house`、`book`、`person.crop.circle`，选中使用相应填充版本。
- 背景以暖白色为主，可保留极淡的顶部分隔线。
- 学习详情隐藏 Tab 栏，突出学习任务。
- 若原生组件无法满足目标系统上的必要视觉要求，再评估自定义实现，并补齐安全区、选中状态与 VoiceOver。

页面跳转使用 `NavigationStack`，并遵循项目最低支持版本。主要按钮按下时可轻微缩放至 0.97，并提供轻触觉反馈。装饰动画克制；开启「减少动态效果」时关闭位移与循环动画。

## 9. 图片素材规范与交付约定

### 9.1 所有图片由本对话中的 Codex 生成

实现 AI 的职责是接收、导入和使用图片，不承担图片生成工作。需要新增或调整图片时，整理资源名、用途、目标比例与问题，反馈给用户转交本对话中的 Codex。

功能性图标（返回、播放、书签、导航等）使用 SF Symbols 或现有原生图标资源，不属于需要生成的插画。

### 9.2 统一插画风格

温暖明亮的儿童绘本插画，细腻水彩与轻柔手绘笔触，中国山水意境，圆润亲切的角色，清楚的前中后景，金黄色和自然蓝绿色为主。避免过度写实、强烈塑料质感和不同素材间的明显画风差异。

南瓜角色固定设定：

- 金黄色南瓜身体、绿色卷曲藤柄。
- 深棕色眼睛、柔和腮红、开心表情。
- 蓝色围巾、短而圆润的四肢。
- 阅读、探头、举卡庆祝三种姿态保持相同脸型、比例与材质。

首页三张图与成长页采用角色直接画入场景的一体图片。独立读书、庆祝姿态仅保留为设计参考，不进入当前正式资源包；`mascot_peeking` 继续用于解释卡片。禁止重复叠加角色。

### 9.4 素材交付与接入流程

1. 本对话中的 Codex 按清单生成并检查素材，提供实际文件及资源名映射。
2. 交付说明记录实际像素尺寸、透明背景情况、建议裁切与构图焦点。
3. 实现 AI 导入正式包的 `PoetryArtwork.xcassets`，或合并其中 imageset，避免同名资源重复。目录已采用单一通用图片设置，保持原始像素，不需自行重复生成 1x/2x/3x 文件。
4. 背景保持比例；三张首页应优先按正方形比例显示完整构图，不拉伸、不切掉贝贝、书本或树下位置。只有卡片覆盖的底部草地可少量裁切。
5. 图片正式交付前，界面资源引用可先通过统一的资源封装连接占位内容；不能因为缺少图片而崩溃。
6. 如遇裁切、角色位置或背景文字区冲突，实现 AI 记录具体问题，由本对话中的 Codex 修订图片。

不要从参考图中截取手机边框、状态栏、导航或按钮作为 App 图片资源。参考图外侧的独立南瓜仅用于角色设定参考。

## 10. SwiftUI 组件与实现组织

推荐组织方式，可适配现有项目结构，不强制重构已有业务模块：

```text
AppTheme
├── Colors
├── Typography
├── Spacing
└── CornerRadius

Shared Components
├── IllustratedSceneHeader
├── PaperSurface
├── PrimaryGoldButton
├── AudioButton
├── MascotIllustration
└── CollectionCover

Screens
├── TodayView
│   ├── ContinueLearningCard
│   └── LearningShortcutCard
├── PoemLearningView
│   ├── PoemLineView
│   ├── LineExplanationView
│   └── LearningActionBar
└── GrowthAlbumView
    ├── ThemeCollectionShelf
    └── LearningStatsPanel
```

实现要求：

- 用 `ZStack` 表达完整场景与原生文字、卡片的前后关系。首页与成长页不再用独立图层拼南瓜，解释框助手除外。
- 用 `ScrollView` 承载纵向内容。
- 用 `safeAreaInset(edge: .bottom)` 放置学习操作栏。
- 仅背景延伸到安全区外，文字和操作遵守安全区。
- 装饰图片关闭不必要的命中测试，避免遮挡按钮。
- 不使用大量固定坐标拼整页；根据容器宽度、内容长度和动态字号布局。
- 使用语义字体与 `@ScaledMetric` 等机制支持动态字体。
- 不在 App 内绘制假的刘海、灵动岛、状态栏或手机外框。
- 装饰插画对 VoiceOver 隐藏，按钮提供清晰标签，诗句按合理顺序阅读。
- 加载、正常、无记录、音频不可用和完成状态均需可展示。
- 首版按参考图的浅色方案实现；深色模式另行设计，不能直接反转插画颜色。
- 背景图片按实际显示需求加载，控制解码与内存开销，避免为小图标加载超大位图。

## 11. 实施顺序

1. 阅读现有 Swift 项目，确认导航、数据结构、语言设置和最低 iOS 版本。
2. 建立主题变量与通用纸面、按钮、场景组件。
3. 搭建三屏结构，接入真实数据和现有交互，按显式诗歌主题配置资源映射。
4. 导入正式资源包，校准层次、裁切、留白和文字可读性，确保首页三图不再叠加独立角色。
5. 验证各页面状态、小屏大屏、动态字号和 VoiceOver。
6. 提供三屏运行截图，与用户参考图对照验收。

图片生成可以与原生布局开发分开推进。实现 AI 不需要等待所有素材才开始编码，也不能省略最终素材接入和视觉验证。

## 12. 验收标准

- 首页第一眼能看到山水场景、南瓜伙伴和继续学习入口。
- 场景与内容之间自然交叠，没有生硬的图片分界。
- 学习详情以诗句为中心，插画不干扰阅读。
- 成长页有收藏册趣味，主题入口与统计信息清楚。
- 三屏的南瓜形象、插画笔触、纸面与按钮质感一致。
- 所有文本和操作均为原生组件，真实可交互。
- 页面统计来自真实数据，语言和音频选项与实际支持能力一致。
- 小屏、大屏和大字号下不遮挡、不截断关键内容。
- 装饰图片不拦截点击，底部操作不遮挡正文。
- 不使用 Emoji、随机插画或整屏截图代替正式视觉资产与原生界面。
- 所有生成图片来自本对话中的 Codex；缺失素材明确记录，不能以占位图宣布视觉还原完成。

最终目标：像一本可以互动的国风儿童绘本，操作清楚、阅读舒适，同时保留原型中的温暖、陪伴感与诗意。
