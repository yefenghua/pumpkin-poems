# 第三阶段：社交游戏版功能与排期

- 状态：规划草案；玩法、时限和分值为待试用的建议值。
- 更新日期：2026-10-22
- 前置文档：[第二阶段：学习试用版](phase-2-learning-release.md)
- 基础批次 3A：6—8 周，交付私密房间、多人飞花令、好友周榜。
- 扩展批次 3B：追加 4—6 周，交付合作挑战与主题赛季；可按反馈延期。

## 1. 目标与前置条件

让孩子与熟悉的同伴一起运用古诗，比赛后能够发现想补学的诗句。竞技得分与学习掌握状态分开，不能因为游戏赢了就自动判定已掌握某首诗。

进入阶段前应具备第二阶段的账号、儿童档案隔离、审核诗库与内容版本管理。若第二阶段只交付四周 P0 版本，需要先补齐账号与权限能力。

先采用邀请进入的私密房间和好友小组。陌生人随机匹配、私聊、语音聊天、公开作品社区不进入本阶段。班级榜在第四阶段建立正式师生与班级关系后启用。

## 3. 私密房间与好友关系

### 3.1 建房与加入

房主选择主题、难度、固定题库、计时方式，然后生成邀请码。默认 2—4 人，不开放房间搜索。邀请码建议有效 10 分钟，仅用于请求加入；房主确认后才能进入准备区，不凭邀请码读取好友或学习档案。

准备页展示诗库范围、规则、每轮时长和是否参与本周计分。开始前所有玩家完成资源准备与确认；某人缺少必要内容时先下载，不能开局后才发现答案或音频不可用。

建议用同主题、同难度的审核诗库作为题库。题库不向对手公开个人学习历史；未学篇目可以先预习。房间创建后固定内容版本，进行中的比赛不因线上内容更新而改变答案。

### 3.2 好友小组

通过明确邀请建立小组，不读取系统通讯录、不按真实姓名搜索。孩子发起邀请后由家长区域确认关系；成年人账号与儿童学习档案的权限分别控制。

小组成员只能看到昵称、预设头像、参与公开的本组游戏成绩，不可查看作品草稿、完整学习记录和其他小组成员关系。移除好友、屏蔽或退出小组后，后续邀请与访问立即失效。

首版提供预设头像、昵称规则和固定鼓励短语，例如「好詩句！」「一起再試一次」。不允许任意文字聊天，比赛输入仅用于判题，未通过校验的输入不转发给其他玩家。

## 4. 多人飞花令规则

### 4.1 基础玩法

| 项目 | 建议规则 |
| --- | --- |
| 玩家数 | 2—4 人 |
| 回合数 | 每人 2 个答题回合，约 4—8 分钟；以实际试用调整 |
| 目标字 | 每局从题库中选择一个字，开局前验证存在足够的不重复答案 |
| 顺序 | 随机确定第一位，后续按固定顺序轮转，第二轮轮换起始位置 |
| 答题时长 | 默认每回合 60 秒；慢速房可选 90 秒，并使用独立榜单规则 |
| 有效答案 | 审核题库中的完整诗句，包含目标字，且本局未被使用 |
| 输入方式 | 手动输入；兼容繁简、允许的异体字、空格和标点差异 |
| 提示 | 每回合一次首字提示；使用后仍可完成，但分值降低 |
| 错误 | 显示原因，在剩余时间内最多重新提交两次；重复请求不算重试 |
| 超时／跳过 | 本回合 0 分，进入下一位，不淘汰玩家 |
| 结算 | 所有回合结束后按个人总分排序，同分并列 |

目标字的可用答案数量至少达到所有玩家总回合数的两倍；不满足时换字或换包。自由输入界面随时可查看题库范围。

### 4.2 判题边界

判题依次检查回合归属与有效期、输入规范化、题库匹配、目标字、重复诗句。繁简版本共用同一答案 ID；异体字仅依据审核映射处理，不使用任意模糊匹配认定正确。

- 已收录但不含目标字：提示与本轮要求不符。
- 已被使用：提示本局已出现，并展示出处。
- 尚未收录：提示「此句暫未收錄於本輪詩庫」，不宣称该诗句错误。
- 未收录输入仍受当前回合时限约束；可换一句继续，不额外暂停全局时间。
- 同一句因不同繁简、标点或出处别名输入，不可重复得分。

客户端本地校验用于即时提示，最终结果由 Go 服务验证。客户端不能自行提交“答对”或最终分数作为权威结果。

### 4.3 得分与公平性

建议无提示正确得 10 分，有提示正确得 6 分，跳过或未完成得 0 分。每人两回合，上限 20 分。默认不设置速度奖励，避免把输入速度当成古诗能力。

不同题库、提示规则、回合数和时长的成绩不得混在同一榜单。儿童不因短期排名低而丢失已收集的诗词卡。

## 5. 对局状态与异常处理

房间状态为：等待加入 → 准备 → 进行中 → 结算中 → 已完成；另有已取消和故障中止。每次状态更新有序号，客户端收到旧状态时不覆盖新状态。

| 场景 | 产品行为与服务端规则 |
| --- | --- |
| 房主在开始前离开 | 转交已准备成员；无人可接管时解散 |
| 进行中房主离开 | 对局由服务端继续驱动，不依赖房主设备 |
| 短暂断线 | 显示重连；服务端计时继续，重连后恢复快照和当前回合 |
| 断线期间轮到本人 | 可在剩余时间内回来作答；到时按超时处理 |
| 同一回合重复提交 | 请求 ID 去重；首次有效结果保留，不能重复得分 |
| 到时边界提交 | 以服务端接收时点和回合截止时间判定；设备时钟不决定结果 |
| 主动退出 | 提示会错过剩余回合；其后回合记为未完成，其他成员继续 |
| 活跃玩家不足两人 | 转为个人练习，保留已答记录，但本局不计竞争榜 |
| 服务不可用或结果无法确认 | 标记故障中止，保留可恢复的练习记录，不扣已有积分、不写入排名 |
| 结算响应丢失 | 重连查询同一比赛结果，不能再次生成结算或奖励 |
| 内容被确认存在错误 | 停止用于新局；受影响榜单成绩可撤销并解释原因，不静默改判 |

网络异常与恶意行为区分处理。服务端校验和限流是首版范围，复杂作弊识别模型不作为首版前置条件。

## 6. 排行与学习反馈

### 6.1 好友周榜

首版先做好友挑战周榜。以香港时间 `Asia/Hong_Kong` 周一 00:00 至下周一 00:00 作为一个统计周期；比赛按服务端完成时间归属。界面明确显示结算时间。

每个榜单绑定固定周挑战题库与规则版本，取每人当周最高的 5 局有效成绩之和；最多计 5 局，每局最高 20 分，周分上限 100。可以继续练习，但不会无限增加周分；相同总分并列。

每周开始冻结该期参与成员。新加入者可参加练习，下周进入正式周榜。退出或关闭排名后，其昵称从当前展示中移除；成绩保留范围由账户数据规则处理，不向已退出成员继续开放榜单。

用户可隐藏自己的榜单位置，仍保留个人最好成绩。空榜显示邀请或练习入口，不用机器人伪装真人补足榜单。

### 6.2 进步与复习榜的边界

第三阶段首发以服务端判定的游戏成绩排名。第二阶段的离线学习事件用于个人报告，不能直接拿来进行可信竞争计分。

学习进步、复习完成榜列为后续推荐项：先定义同等任务机会、有效任务上限和在线验证规则，再上线。第四阶段班级榜也遵循此约束。

### 6.3 结算页

展示自己的得分、独立完成次数、提示次数和本局出现的诗句。孩子可点击任一句查看出处与释义，将其中尚未学习的篇目加入“待学”，不会直接标记为已读或已掌握。

比赛结果与学习建议分别呈现。例如「你獨立答出了兩句含『月』的詩」以及「看看另一位詩人如何寫月亮」。

## 7. 扩展批次 3B

### 7.1 诗词接力

2—4 人合作，每人轮流补全一句；初级为上下句，中级为相同意象或主题接力。优先使用点选与词组拼接，避免低龄用户因输入速度失去参与机会。

每人至少获得一次作答机会；可以请求队友提供预设提示。任务完成后回看全诗和释义，不按手速抢答。缺席成员的任务在超时后转为团队共同完成。

### 7.2 合作修复诗卷

一张诗卷分为字词、排序、诗意三个任务区，每位成员获得与其选择难度相符的任务。成员可请求交换或帮助，但不能未经同意替别人提交答案。

全部区域完成后合成完整诗卷，展示原诗、场景与团队共同解锁的主题卡。奖励按有效参与发放；进入后全程无操作不自动记为完成。首发先交付一个主题和一套完整任务模板。

### 7.3 主题赛季

先试行 2—4 周主题活动，由学习、跨日复习和一次合作挑战组成。完成任务可得纪念卡；不设置付费抽取或靠无限比赛刷分解锁。

规则固定开始与结束时间、参与资格、任务 ID、补领规则。赛季结束后学习内容仍保留，已获得卡片不清空。活动结束时的进行中对局允许完成，但是否计入活动以预先展示的服务端结算截止规则为准。

## 8. 技术与运营分工

| 责任方 | 工作 |
| --- | --- |
| Swift | 房间与准备页、答题输入、剩余时间展示、重连、结算、榜单与学习跳转 |
| Go | 邀请与权限、房间状态机、回合时钟、答案验证、结算事务、榜单、限制与审计 |
| 内容 | 主题答案集合、异体字映射、难度标注、合作题、释义与出处审核 |
| 产品／设计 | 规则说明、慢速模式、断线与退出文案、固定互动短语、参与反馈 |
| 运营／测试 | 邀请试用、异常对局核查、举报处理、网络与并发场景验证 |

HTTP 用于配置、邀请和历史结果，WebSocket 用于房间与回合事件。服务端保存可恢复的比赛状态和唯一结算记录。可按实际并发引入 Redis，不以拆分独立游戏微服务为前提。

上线前确认试点并发量；初始容量验证可用 50 个同时进行的房间作为候选目标，属于待确认测试基线，不是已经达到的性能承诺。

## 9. 排期

假设 1 名 Swift、1 名 Go 并行，产品／设计、内容与测试支持到位。3B 的时长独立追加，不能把其全部内容塞进 3A 的六至八周。

### 9.1 基础批次 3A：6—8 周

| 周次 | 重点工作 | 交付 |
| --- | --- | --- |
| 第 1 周 | 规则与题库确定，权限模型，状态机与交互稿 | 房间、回合、排名协议冻结 |
| 第 2—3 周 | 邀请与好友关系、准备区、服务端计时与判题 | 两设备完成一局真实对战 |
| 第 4 周 | 2—4 人、提示、超时、断线重连、重复提交 | 异常条件下仍能正确推进 |
| 第 5 周 | 学习型结算、周榜、隐藏与退出、重复结算防护 | 从邀请到榜单与补学闭环 |
| 第 6 周 | 安全与权限回归、弱网测试、容量验证 | 封闭试用候选版本 |
| 第 7—8 周 | 邀请真实小组试用、调整时长与题库、修复问题 | 稳定的社交游戏基础版 |

### 9.2 扩展批次 3B：追加 4—6 周

| 周次 | 重点工作 | 交付 |
| --- | --- | --- |
| 第 1—2 周 | 复用房间框架，实现诗词接力与任务分工 | 合作玩法可运行 |
| 第 3—4 周 | 一套修复诗卷内容、赛季配置与纪念卡 | 完整主题活动 |
| 第 5—6 周 | 参与公平性、掉线接替、时间边界、真实小组试用 | 扩展批次验收 |

若基础版暴露学习中断或网络可靠性问题，优先修复，3B 可以推迟，也可在第四阶段学校试点后再实施。

## 10. 验收标准

- [ ] 2、3、4 人房间均可完成准备、开局、轮转和唯一结算。
- [ ] 繁简、标点、审核异体字归一后，同一句不可重复得分。
- [ ] 题库固定版本，未收录输入不会被当成错误古诗传播。
- [ ] 提示、超时、退出、重复请求、截止边界和重连按规则处理。
- [ ] 客户端修改分数或设备时钟不能改变服务端结果。
- [ ] 故障中止不写入竞争榜，重复查询不会重复发奖励。
- [ ] 不同题库和规则不混榜；最高五局、并列与周边界计算正确。
- [ ] 非成员不能读取房间、小组榜单或他人的学习记录。
- [ ] 屏蔽、移除、退出与隐藏排名后，对应访问与展示及时更新。
- [ ] 未校验的输入、作品草稿与身份信息不会广播到房间。
- [ ] 结算页可追溯出处，并进入学习流程，不自动提高掌握等级。
- [ ] 3B 发布时，合作奖励、缺席接替和赛季结束行为通过验证。

## 11. 试用与成效观察

建议先邀请 8—12 个熟人小组进行两周试用。记录实际样本量，不将少量样本推广为所有年龄段结论。

| 指标 | 口径 | 判断用途 |
| --- | --- | --- |
| 对局完成率 | 正常结算局数／成功开局数，另列用户退出与服务故障 | 评估规则与稳定性 |
| 答题参与率 | 至少独立提交一次有效答案的人数／进入对局人数 | 检查是否人人有参与机会 |
| 比赛后补学率 | 结算后 24 小时内从该局入口开始学习的人数／完成对局人数 | 判断是否带动学习 |
| 题库外输入占比 | 未收录提交次数／全部有效提交次数 | 判断题库范围是否清楚 |
| 重连恢复率 | 恢复有效比赛状态的重连次数／发起重连次数 | 判断网络体验 |
| 次周同伴再参与 | 下一周再次参与的小组数／可完整观察两周的小组数 | 观察同伴互动持续性 |

游戏参与上升但核心学习与复习下降时，应调整入口和活动任务，不单纯增加奖励强度。
